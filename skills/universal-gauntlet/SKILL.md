# Universal Gauntlet skill

Use this skill when asked to build, improve, or rigorously evaluate software with the Universal Gauntlet Runtime.

## Workflow
1. Inspect repository and config.
2. Establish objective and concrete acceptance criteria.
3. Run `gauntlet doctor` when provider availability is uncertain.
4. Select builder and independent critic by role/capability, not brand preference.
5. Use `workspace` for authorized coding CLIs, `patch` for API/local models, and `advisory` for critics/architects.
6. Run deterministic verification after every builder attempt.
7. Give critics evidence, not builder intent.
8. Revise until verification and critic policy pass.
9. Run final adversarial review.
10. Report `GAUNTLET PASSED` only if every required gate passed.

For WebUI work, enable browser verification and require fresh Chromium evidence after material changes.
